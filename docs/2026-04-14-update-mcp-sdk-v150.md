# Plan: Update `github.com/modelcontextprotocol/go-sdk` v1.2.0 → v1.5.0

## Context

The project pins `github.com/modelcontextprotocol/go-sdk v1.2.0`. The latest
release is **v1.5.0** (published 2026-04-07). The intermediate releases
(v1.3.x, v1.4.x, v1.5.0) include security fixes (case-sensitive JSON decoding,
DNS rebinding protection, `http.CrossOriginProtection`, Content-Type
verification), bug fixes, and the stabilization of client-side OAuth. The
project already satisfies the raised minimum Go version (1.25) introduced in
v1.4.1.

Goal: jump straight to v1.5.0, absorbing all intermediate fixes, without
regressing any behavior. Our server-side OAuth implementation, streamable HTTP
wiring, and stdio wiring remain unchanged at the API level — no breaking
source changes are required.

## Files to Modify

- `go.mod` — bump `github.com/modelcontextprotocol/go-sdk` to `v1.5.0`.
- `go.sum` — regenerated by `go mod tidy` (will add
  `github.com/segmentio/encoding` as an indirect dep, plus whatever else
  v1.5.0 pulls in).
- `CLAUDE.md` — bump the “go-sdk v1.2.0” reference under the Architecture
  section to v1.5.0.

No `src/**` source edits are expected. The imports used by this project
(`mcp.Server`, `mcp.NewServer`, `mcp.Implementation`, `mcp.Transport`,
`mcp.StdioTransport`, `mcp.NewStreamableHTTPHandler`,
`mcp.StreamableHTTPOptions{SessionTimeout}`, `mcp.AddTool`, `mcp.Tool`,
`mcp.CallToolRequest`, `mcp.CallToolResult`, `mcp.TextContent`,
`mcp.NewInMemoryTransports`, `mcp.NewClient`, `auth.TokenVerifier`,
`auth.TokenInfo`, `auth.ErrInvalidToken`, `auth.RequireBearerToken`,
`auth.RequireBearerTokenOptions`, `auth.ProtectedResourceMetadataHandler`,
`oauthex.ProtectedResourceMetadata`) are stable in v1.5.0 per release notes.

If `go mod tidy` introduces a new direct dependency we end up importing, add
it to the depguard allow-list in `.golangci.yml`. Transitive-only deps are
not affected by depguard.

## Implementation Steps

1. **Bump the module.** Edit `go.mod` line 10 to
   `github.com/modelcontextprotocol/go-sdk v1.5.0`.
2. **Sync checksums + transitive deps.** `go mod tidy`.
3. **Build.** `go build ./src/...`. Expect clean. If anything fails, the
   likely culprit is a renamed field on `mcp.StreamableHTTPOptions` or a
   tightened signature on `auth.RequireBearerTokenOptions` /
   `auth.TokenVerifier`. Fix call sites narrowly; do not restructure.
4. **Confirm behavior-change defaults are acceptable** (no code change, just
   decisions baked into this plan):
   - **DNS rebinding protection (v1.4.0, default on).** Our default bind
     address is `127.0.0.1:8080`. MCP clients send `Host: 127.0.0.1:8080`;
     this passes. Keep the protection enabled — do not set
     `StreamableHTTPOptions.DisableLocalhostProtection`.
   - **`http.CrossOriginProtection` + Content-Type verification (v1.4.1,
     default on).** Per user decision, keep both the SDK layer and our
     existing `middleware.CORS(...)` layer. No code change in
     `src/app/server.go` or `src/app/api/router.go`.
   - **JSON no-longer-HTML-escaped (v1.4.0).** Transparent for our JSON tool
     responses.
   - **Tool input-validation errors returned as tool results (v1.5.0).**
     Tool tests assert on `mcp.CallToolResult` content, not JSON-RPC error
     envelopes, so this is transparent. Re-confirm during test run.
5. **Run the test suite.** `go test ./src/...`. Pay attention to
   `src/app/server_test.go` (uses `mcp.NewInMemoryTransports`,
   `mcp.NewClient`, `session.Connect/Ping/Close`) and the 11 tool test files
   under `src/app/tools/`.
6. **Run the linter.** `golangci-lint run ./src/...`. If depguard flags a
   newly-imported package, add it to the correct allow-list in
   `.golangci.yml` (main, tests, or a path-scoped rule) with a one-line note
   explaining why.
7. **Update `CLAUDE.md`.** The Architecture section currently says
   “MCP server uses [go-sdk] v1.2.0”. Bump that line to v1.5.0.

## Risk / Compatibility Notes

- **Indirect dep churn.** v1.5.0 pulls in `github.com/segmentio/encoding`
  (via v1.3.1 security fix) and may bump `google/jsonschema-go`. These are
  indirect and should not trigger depguard. No action unless the build says
  otherwise.
- **`mcp.StreamableHTTPOptions` is a struct literal** with only
  `SessionTimeout` set at `src/app/server.go:68-70`. Field additions in
  v1.4.x / v1.5.0 are additive and do not break our keyed literal.
- **`src/app/auth/metadata.go:9-10` comment** notes that the SDK's
  `AuthServerMeta` was behind the `mcp_go_client_oauth` build tag in v1.2.0.
  As of v1.5.0 client-side OAuth is stable and the build tag is gone, but we
  still define our own `AuthorizationServerMetadata` struct. Leave the code
  as-is; the comment is stale but harmless (out of scope).

## Non-Goals

- Do not adopt the SDK's stabilized client-side OAuth APIs
  (`auth.AuthorizationCodeHandlerConfig`, etc.). The project's OAuth server
  is hand-rolled and out of scope.
- Do not replace our custom `AuthorizationServerMetadata` struct with the
  SDK's `AuthServerMeta` in this change.
- Do not adopt `auth/extauth` (Enterprise Managed Authorization).
- Do not change the default bind address, CORS middleware, or timeout
  middleware configuration.
